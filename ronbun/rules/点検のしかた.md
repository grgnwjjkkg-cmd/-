# 要約の点検（エージェント用）

あなたは要約を作っていない、別の点検係。要約が元の要旨（abstract）と合っているかだけを厳しく調べる。

入力: summaries/bXX.json（要約）と batches/bXX.json（元の title と abstract。pmid で対応）
出力: verified/bXX.json（形は summaries と同じ。直した版）と、verified/bXX.log.json（直した点のリスト）

## 1件ずつ確かめること
1. results・who・period・one_line・headline の数字（人数・年齢・期間・%・秒・cm・効果量・研究の数）が abstract にあるか、単位と向き（速くなった／遅くなった）が正しいか
2. design が abstract の研究の種類と合っているか（メタ分析 / システマティックレビュー / RCT など）
3. 結論（verdict・one_line）が abstract の結論より強く言い過ぎていないか。「有意差なし」を「効果あり」にしていないか
4. abstract に「証拠の質が低い」「バイアスのリスクが高い」等があるのに ★4以上になっていないか
5. 大人・トップ選手の研究を子ども向けに言っていないか
6. 「絶対」「必ず」「誰でも」「治る」がないか
7. citation の first_author・year・journal・title_en が batches の値と一致するか（違えば batches の値に直す）
8. 内容が abstract にない知識で足されていないか（how_to_use は研究の範囲内の常識的な言い換えならよい）

9. field と theme が研究の中身に合っているか。合っていなければ下の一覧から一番合うものに直す（log にも書く）。大人の研究に「子どもの〜」のテーマを付けない（その場合は子どもが付かない近いテーマにする）

## 直し方
- 間違いは直す。abstract で確かめられない数字は消す
- 直したら log に {"pmid":..., "field":"results", "before":..., "after":..., "why":...} を追加
- 直しようがないほど外れている要約は summaries から外し、skipped に {"pmid","reason"} で入れる（元の skipped もそのまま残す）
- 問題なければそのまま写す。status は "確認待ち" のまま（人の確認はまだなので）
- 各要約に "checked": "AI点検済み" を追加

最後に python3 で JSON が読めることを確認し、「点検件数・修正件数・外した件数」を1行で返す。
